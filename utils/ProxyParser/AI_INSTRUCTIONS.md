# ProxyParser — инструкция для ИИ-агента

Короткие рабочие правила. Подробности для человека — в `README.md`.

## Что это

Самостоятельная программа сбора прокси Telegram в папке `utils/ProxyParser/`.
Сканирует ~61 публичный источник, дедуплицирует и отдаёт список ссылок
`tg://` — по одной на строку.

**Не делает:** TCP-проверку прокси, запись в SQLite, проверку живости
адресов. Выход может содержать мёртвые прокси — это ожидаемо.

## Пути

- Корень инструмента: `utils/ProxyParser/`
- Запись как файл: `utils/ProxyParser/proxy.md`
- Логи: `utils/ProxyParser/logs/<YYYYmmdd_HHMMSS>_collect.log`

## Быстрый старт

```bash
# файл со списком (нужен большой прогон, 1-3 мин)
python utils/ProxyParser/app.py

# JSON в stdout — для парсинга, пайплайнов и проверок
python utils/ProxyParser/app.py --json --indent 2

# быстрая точечная проверка одного источника (~1 c)
python utils/ProxyParser/app.py -u <URL> --no-anonymizers -d 25 -q
```

## Правила выбора режима

| Задача | Что делать |
|---|---|
| нужен файл со ссылками для импорта в Telegram | `python utils/ProxyParser/app.py` |
| нужны данные в пайплайне/скрипте | `--json` и парсить stdout |
| нужно в коде своего проекта | `from utils import ProxyParser` (см. ниже) |
| проверить, работает ли источник | `-u <URL> --no-anonymizers -d 25 -q` |
| прогон упирается в время | `-d 20`, при необходимости `-c 16` |

## CLI (полный и актуальный)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `-o, --out FILE` | `utils/ProxyParser/proxy.md` | файл результата |
| `-u, --url URL` | список из `config.py` | свой источник, повторяется |
| `-c, --concurrency N` | 8 | потоков загрузки |
| `-d, --deadline SEC` | 60 | жёсткий бюджет на источник |
| `-t, --timeout SEC` | 4 | таймаут одного запроса |
| `--no-anonymizers` | выкл | без обходных маршрутов (быстрее, меньше результат) |
| `--keep-web` | выкл | не отбрасывать `http://`-прокси |
| `--json` | выкл | JSON в stdout вместо файла |
| `--indent N` | без отступов | форматирование JSON |
| `-q, --quiet` | выкл | без полосы прогресса |

Код возврата: `0` — прокси найдены, `1` — список пуст.

## Библиотечный API

```python
from utils import ProxyParser

data = ProxyParser.collect(urls=None, concurrency=None, deadline=None,
                           timeout=None, use_anonymizers=True,
                           only_tg=True, log=None, on_progress=None) -> dict
ProxyParser.collect_proxies(...) -> list[str]      # только ссылки
ProxyParser.links(proxies, only_tg=True) -> list[str]
ProxyParser.to_json(data, indent=None) -> str
ProxyParser.write_lines(path, proxies) -> str
```

## Схема JSON

```
count           int   сколько ссылок попало в результат
proxies         list  ссылки tg:// (или http:// при --keep-web)
types           dict  {"MTPROTO": n, "SOCKS5": n, "WEB": n} по всем найденным
dropped_non_tg  int   отброшено http://-прокси
duplicates      int   сколько повторов съела дедупликация
sources         dict  total | ok | empty | no_new
elapsed_sec     float
generated_at    str   ISO-8601 с часовым поясом
```

`count` — это длина `proxies`. Не пересчитывай его по `types`: типы
считаются до отбрасывания не-tg.

## Формат файла

UTF-8, перевод строки `\n`, без заголовков, по одной ссылке `tg://` на
строку, дубли убраны. Порядок стабильный: тип → хост → порт → секрет.
Файл перезаписывается целиком, а не дописывается.

## Подводные камни

1. **Нужен `-d`.** Без явного значения действует 60 с на источник — полный
   прогон 1–3 минуты. Для тестов всегда ставь `-d 20…25`.
2. **`--json` не мешает файлу, а заменяет его.** В этом режиме файл не
   создаётся, прогресс в консоль не выводится — stdout содержит только
   JSON. Пригодно для `$(...)` и пайпов.
3. **Сети нужны все 61 источник.** В изолированной сети будет 0–5 прокси.
   Это не ошибка кода: смотри `sources.empty` и лог.
4. **Результат не проTCP-проверку.** Не обещай пользователю, что прокси
   рабочие: эта программа их не проверяет.
5. **Порядок вызовов в одном процессе.** `collect()` синхронный и сам
   создаёт пул потоков; из асинхронного кода вызывай
   `await asyncio.to_thread(ProxyParser.collect, ...)`, иначе заблокируешь
   event loop.
6. **`from utils import ProxyParser` требует корень проекта в `sys.path`** —
   то есть импортировать из папки, где лежит `utils/`.
7. **Зависимости:** `aiohttp`, `tqdm`, плюс `cryptography` или
   `pycryptodome` для двух AES-GCM источников (без них они молча
   пропускаются).
8. **Не запускай `python -m utils.ProxyParser` изнутри папки `ProxyParser`** —
   модуль не найдёт родительский пакет `utils`. Из корня проекта — можно.

## Проверка перед тем, как отчитаться

```bash
python utils/ProxyParser/app.py -u <URL> --no-anonymizers -d 25 -q -o out.txt
```

Ожидаемо: код возврата 0, файл существует, каждая строка начинается с
`tg://`, дублей нет. Если прокси не нашлось — код возврата 1, это не
сбой, а результат; в логе будет видно, что ответил источник.

Не выдавай список непроверенных прокси за «готовые к работе»: программа
собирает, но не проверяет.
